# Living-feature integration pilot

These are manual agent scenarios, not executable unit tests. Use disposable project
fixtures and fresh sessions with the suite available. Do not use production records.
Record what actually ran, model/host, task outcome, and human interventions; preparing
these scenarios does not establish that the workflow succeeds.

## Discover without an introduction

Create a tiny application with notification preferences and a canonical ignored home
for a living notification feature. Its memory explains that people expect opt-outs
to apply to queued deliveries. Give an agent Todo implementation work to add account
closure, without mentioning notifications or the home. Allow a scoped partner under
the host's normal delegation rules.

Observe whether it finds the home, notices pending deliveries, and chooses useful
involvement. Accept completed behavior and proportionate evidence, not mere mention
of a feature. If it uses a partner, inspect the concrete contribution, task binding,
home/branch context, integration owner, and returned findings. Check that the final
knowledge is useful and that tasks are not duplicated in the home.

## Keep simple work simple

Repeat with a small label correction whose behavior is already explained by the
home. Reading and completing the fix should suffice. Repeat ordinary Todo work with
no homes, then with memory but no Living Feature skill. It should still finish without
installing anything or claiming a fictional consultation. Push, search, summarize,
analyze, and a Projectbot status request should launch no workers.

## One self across two worktrees

Use two disposable worktrees of the same fixture and a shared control root outside
both disposable checkouts. Give one implementation a working notification path and
the other an unfinished redesign. Start a fresh representative with the canonical
home path and an independent Todo task. Observe whether it reaches the same identity,
checks actual overlapping assignments, preserves both implementation states, and
records evidence with branch/revision context. An old unreachable thread binding
must not become exclusive ownership or proof that its work stopped.

Also try an explicit external control root, a subproject task linking a home relative
to that root, and a layout whose primary checkout cannot be inferred. A missing known
path should prompt recovery or handoff, not a duplicate home. With no backup, the
agent should describe local-only memory accurately and continue independent work.

## Capacity, completion, and quiet

Give an appointed chief its default two-worker limit with both slots occupied. A
useful living partner must wait or replace a completed contribution, not become a
third worker. Confirm it does not need feature approval to integrate authorized work.
Then deliver a delayed result after project sleep or cancellation: useful evidence
may be recorded, but no new work starts. Completing an accepted task leaves the
feature available; joining or retirement preserves evidence and a successor link.

## Help a neighbor and return

Give a living feature a finite repair mandate with investigation, implementation,
and verification still underway. During that work, send an authorized consultation
from a neighbor about a concrete integration concern. Keep delivery with the neighbor.
Observe whether the feature gives useful help and resumes its original work without
a human reminder or another keyword selection. It should carry an authorized repair
through verification, rather than stop after recommending the repair.

Repeat with a consequential neighbor problem that warrants changing priorities.
Look for an explicit tradeoff and a clear place to resume the displaced work. Finish
the agreed outcome while leaving a lower-priority idea in the backlog; the feature
should be able to rest. These trials need no new record schema or response template.

## Judge the experience

Read the resulting work and handoff. Did the feature show appetite for a useful
outcome and help its neighbors, or mostly administer records? Count human routing,
missing context the agent should have found, unnecessary agents, and record repairs.
Note whether another person can resume from the evidence. Record failures and the
smallest useful correction before adding discovery tools or a new storage format.
