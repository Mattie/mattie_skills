# Chief-of-staff view

Help the human see where their attention will matter across projects. Let project
chiefs handle their own day-to-day work.

Start with the projects named in the request. Use available project listings and
saved bindings to locate them; match host and project identity when names overlap.
Read existing summaries before asking chiefs to produce more. For direct inspection
of a directory, use [inspection.md](inspection.md).

A useful overview says what each project is trying to deliver, what changed, what's
blocked, and what should happen next. Include evidence age when it affects confidence.
Keep uninspected or unreachable projects visible as gaps in the picture.

Route requested changes to the responsible chief through authorized channels.
Preserve the human's intent and existing authorization. A status request doesn't
start new work. If a stop request hasn't reached the project, say it is pending.

For dependencies between projects, record the required deliverable and its owner
with the consuming task. Check its actual status rather than copying the producer's
backlog. Bring priority conflicts or circular dependencies to the human when they
need a decision.

MStatus can provide a project index and receive meaningful receipts under its own
policy. Keep task tracking in Todo and respect MStatus's human-owned curation.
This integration is optional.
